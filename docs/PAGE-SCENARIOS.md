# 逐页异常演示（2026-10-30）

## 使用方式

控制台在**左侧目录与手机之间**，右侧保持原交互说明。切换页面后自动匹配本页操作；统计页打开新增抽屉时，自动切换为保存异常。无需选择流程环节、触发模式或跳转其他页面。

1. 选择本页异常，**立即原地展示**。没有“立即展示 / 操作后触发”按钮、触发模式或次数设置。准备数据只在内存中，不写入已保存数据。
2. 选择“正常状态”或“恢复正常”即移除异常，不自动提交或重放。正常列表直接显示样例，不添加重新加载按钮或入页等待。
3. “恢复操作结果”可选重试成功 / 继续失败。App 内再次执行同一操作也遵守该策略；成功后才写入。
4. **全局环境**独立提供断网、弱网（均为模拟）。选择后作用于本页支持的操作，与局部场景互斥；没有请求的说明页不伪造故障。

手机复用原资源告警、清洁提醒和拍摄失败弹窗；其他保存失败仅更新原操作按钮或说明文案，不添加异样卡片、演示弹窗或 Toast。详细解释及恢复动作放控制台。隐藏控制台不移除当前场景。

### 原异常页面复用

在正常 `/device` 页面直接映射原缺水、出粉、水质、混合仓清洁提醒 / 到期、夜间缺水、清洁未完成、管路清洁提醒共 8 类设计。保留原关闭、排查、去清洁、返回 / 继续入口。原示例路由仍保留，不另建一套样式。

正常背面取景页复用原 `/capture-formula-step2/upload-failed` 和 `/recognition-failed` 弹窗；正面上传失败复用同一上传失败设计，不添加正面不适用的识别错误。

## 页面与流程矩阵

| 页面 / 路由 | 匹配异常 | 操作之后的流程 / 恢复 |
| --- | --- | --- |
| 设备列表 `/` | 持续加载、无设备、加载失败 | 选择即展示，恢复正常即显示设备；无额外加载入口 |
| 设备控制 `/device` | 缺水、出粉异常（仅奶粉）、水质异常、混合仓清洁提醒 / 到期、夜间缺水、清洁未完成、管路清洁提醒、设备超时 | 选择即复用原生告警 / 提醒；原按钮可排查、关闭或去清洁；明确重试成功才生成结果和记录 |
| 配比列表 `/formula-ratio` | 列表加载失败、暂无配比、切换配比失败 | 选择即展示列表状态；失败保留当前配比；重试才切换；空态可扫描添加 |
| 配比编辑 `/formula-edit`（手动 / 识别 / 编辑） | 保存失败、业务校验失败 | 确认 → 等待 → 失败保留输入；重试 / 修改后保存才写入配比；保留原返回上下文 |
| 同步 `/formula-ratio-sync` | 同步失败、超时 | 选择配比 → 确认同步 → 等待 → 失败保留原配比和选择；重试才写入 |
| 正面拍摄引导 `/scan-formula`、`/capture-formula-front` | 相机权限拒绝（模拟） | 开始拍摄 → 模拟打开相机失败；模拟允许重试后才进取景器；可手动输入 |
| 背面拍摄引导 `/capture-formula-back-side` | 相机权限拒绝（模拟） | 同上，恢复后进入背面拍摄 |
| 正面取景 `/capture-formula` | 权限拒绝、照片上传失败、持续上传 | 快门 → 等待 → 停留本页；重试后进入背面引导；也可手动输入；不出现背面识别错误 |
| 背面取景 `/capture-formula-step2`，及 `/upload-failed`、`/recognition-failed` 子路由 | 权限拒绝、上传失败、识别失败、持续上传 | 快门 → 上传 / 识别 → 失败；重试成功才进入配比确认；取消 / 手动录入可用；直接预览不遗留旧静态错误遮罩 |
| 管路清洁 `/device-cleaning` | 启动连接中断、启动超时 | 模式 → 准备 → 开始清洁 → 失败不记完成；重试后进入原正常清洁；除垢仍有第二阶段准备 |
| 喂养统计 `/feeding-stats` | 无记录、记录加载失败 | 选择即展示失败 / 空态；重试恢复列表；空态可添加记录 |
| 新增记录 `/feeding-stats/add-record`，或统计内新增抽屉 | 保存失败 | 保存 → 等待 → 失败保留奶量、时间、喂养人、备注；重试才新增一次；关闭抽屉会取消未完成请求 |
| 设备设置 `/device-settings` | 自动夜灯设置失败（模拟） | 切开关 → 等待 → 失败保持原值；重试才应用 |
| 设备详情 `/device-detail` | 设备名称保存失败 | 编辑名称 → 确认 → 失败保留编辑内容和原名；重试才更新；取消编辑会取消请求 |
| 通知设置 `/notification-settings` | 提醒保存失败、通知权限未开（模拟） | 切开关 → 等待 → 失败保持原值；重试才应用；不真正请求系统权限 |
| 粉水维护 `/powder-water` | 粉水数据保存失败 | 修改 → 保存 → 失败保留输入；不更新容量与补充时间；重试才写入并返回 |

| 缺宝宝 `/no-baby` | 本身已为业务前置条件异常，不额外叠加 | 添加宝宝或忽略返回，沿用原生弹窗与焦点行为 |
| 调奶结果 `/formula-result`、`/formula-result1` | 无新增失败注入 | 已完成业务不伪装成失败；确认 → 无宝宝则补档案，有宝宝则原返回流程 |
| 设备助手 `/device-assistant`、FAQ `/faq` | 无新增失败注入 | 本地帮助入口 / 列表；选择原指引，不伪造远程失败 |

## 全局与重置

- 断网：选择即呈现本页模拟操作失败，不调用成功写入；重连重试或恢复正常。
- 弱网：选择即展示持续等待、不自动写入；可取消，不改变真实浏览器网络。
- 恢复正常：清除注入、停止待处理模拟请求，不自动提交、不重放。
- 重置当前环节：清除该环节异常、数据和计时器；重建**当前准确页面**（不再跳到环节默认页）。
- 重置整个 Demo：仅清除副本隔离存储，回到设备列表，恢复正常环境。
- 导航或表单卸载会取消未完成请求，旧回调不会在离开后写入；刷新默认正常模式。成功的模拟数据仍保留，需全量重置才能清空。

## 边界

37 个场景契约（35 个局部 + 2 个全局），每页均有明确分类；并非给每页强加异常。
仅本地模拟，不扩展登录 / 后端 / 实际硬件权限。清洁中断发生在启动命令及连接检查阶段，未做任意清洁百分比注入。部分统计图与设备信息仍为原样例；设置保持上游页面级生命周期，不扩展跨设备持久同步。未保存输入在主动离开页面后不跨页持久化。原远端图片与外部链接不受模拟断网影响。

验收：`npm test` 包含全部契约、一次性消费、重试、取消、数据隔离、全路由映射测试；`npm run test:e2e` 包含正常流、逐页预览、设置失败回退、相机入口、重置、布局与移动端检查。

相机权限、设备响应超时等原 Demo 没有对应系统界面的故障，仅在控制台解释原因及恢复动作，不伪造系统弹窗。引擎保留旧次数控制接口用于兼容测试，但控制台已完全移除该入口。

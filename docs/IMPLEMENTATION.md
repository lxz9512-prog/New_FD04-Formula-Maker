## 增量架构

```
ScenarioConsole → catalog + ScenarioEngine
                              ↓
           useOperation / useLoadOperation
                              ↓
  原 App 按钮 → loading / error / empty → retry / cancel / edit
                              ↓ 仅成功回调
               原业务状态 / 隔离模拟存储
```

核心文件：

| 文件 | 职责 |
| --- | --- |
| `client/src/demo/catalog.ts` | 场景 ID、环节、前提、操作、模拟结果、延迟、过程文案、异常文案、恢复策略 |
| `client/src/demo/engine.ts` | 外部不可变状态、互斥全局环境、单次 / 持续注入、请求令牌、计时器、重试 / 取消 / 重置 |
| `client/src/demo/react.tsx` | React 订阅、操作注册、直接预览准备、控制台、产品状态层、路由失效边界 |
| `client/src/demo/storage.ts` | 隔离 local/session storage、分环节数据重置白名单 |
| `client/src/demo/scenarios.css` | 独立工具视觉、产品异常卡片、桌面面板 / 移动抽屉适配 |
| `tests/engine.test.mjs` / `tests/storage.test.mjs` | 纯引擎与数据隔离测试，无真实网络 |
| `tests/demo.e2e.mjs` | 浏览器正常流 / 异常 / 恢复 / 重置 / 移动端验收 |

页面只向 `useOperation` 注册操作、成功提交、取消、编辑及业务前提。延迟和注入选择统一在引擎内；没有在各页面编写 `if (sceneId === ...)` 的异常分支。唯一业务适用判断是出粉异常只匹配奶粉模式；业务页面继续负责自身合法性校验。

### 请求和数据一致性

- 每个事务持有递增令牌，只有当前令牌可完成；同时最多一个业务请求，等待期间阻止重复提交。
- 注入失败只更新业务状态，不调用成功写入回调。配比、记录、原料扣减、调奶结果只在成功时写入。
- 单次场景在匹配操作**开始**时消费，不是设置时消费；不相关操作不会误消费。
- 重试继续失败复用同一操作和输入；重试成功仅覆盖本次结果，不清除持续场景。
- 直接预览错误立即显示；加载 / 弱网直接预览只保留等待态，不会在后台自动提交。需要恢复时由演示者明确点击重试或重新执行操作。
- 路径 / 查询参数变化时失效旧请求；路由内容以 pathname、search、reset revision 为 key，确保旧页面卸载，清理原调奶 / 清洁 / 成功提示的定时器。
- 同环节重置也递增 revision，重建表单 / 本地步骤，避免旧闭包覆盖新状态。
- 异常取消保留页面输入和选择；主动离开表单页面视为放弃草稿（不额外跨页持久化未保存输入）。失败时没有“假成功”写入。
- 两种清洁正常流程保留，提醒页的自动启动也经过统一清洁启动边界。

### 重置拥有的数据

| 环节 | 清除的模拟数据 | 保留 |
| --- | --- | --- |
| 设备列表 | 无持久业务数据，重新加载初始设备样例 | 配比、记录、原料 |
| 调奶 / 出水 | 原料余量、清洁杯数、临时调奶结果 | 配比、已成功的历史记录 |
| 拍摄 / 识别 | 临时拍摄上下文，页面内步骤 | 已保存配比 |
| 配比编辑、设备同步 | 配比列表、当前配比、配置状态 | 喂养历史、原料 |
| 清洁 | 清洁完成标记及页面进度 / 定时器，固定初始杯数 | 其他业务数据 |
| 喂养记录 | 调奶历史、手动记录、宝宝资料 | 配比、原料 |
| 全部 | 仅本副本前缀下全部 local/session 数据，全部注入与等待 | 原 Demo / 其他应用的存储键 |

“恢复正常”只终止引擎的当前等待 / 异常；已经成功进入原正常清洁流程的定时器不属于异常注入，不会被该按钮重放或伪装成功。要停止原流程并回到起点，使用环节 / 全部重置。

## 展示位置调整

控制台位于目录与手机之间，采用原 Demo 的奶油色 / 棕色系；右侧原交互说明及连线恢复。引擎状态仍统一管理，新增模拟状态仅在控制台的非模态结果区渲染；手机框架不再挂载演示异常遮罩，结果变化不移动焦点。隐藏控制台不停止注入，也不会自动展开。原业务弹窗不变。

## 明确限制

1. **纯本地模拟**：权限拒绝不会真的请求或撤销系统相机权限；摄像头、照片、OCR、设备命令、断网与弱网均为模拟，控制台及状态卡片明确标注。原项目没有真实登录业务，因此未添加“登录失效”这种不成立的异常。
2. **清洁异常边界**：新增中断 / 超时发生在启动命令及模拟连接检查阶段；重试后从原正常清洁第一阶段开始。未提供任意百分比故障注入、断电续洗、真实固件状态回读。正常深度除垢仍保留两阶段和第二轮准备操作，高温杀菌保留原演示时长。
3. **全局影响范围**：只影响接入 `useOperation` 的设备 / 模拟服务请求，不修改浏览器 `navigator.onLine`，也不拦截应用路由、静态图像或外部链接。离线状态下可返回页面和修改输入，但提交会失败。
4. **统计图**：新保存记录及调奶历史会出现在记录列表；日 / 周 / 月折线和部分汇总仍为原样例序列，不是完整真实统计计算系统。
5. **视觉资源**：保留原远端奶粉照片 / 部分附属设备图片。真实离线时这些旧资源可能不可用；主要 FD04 设备图和新异常机制不依赖它们。不会靠真实图片加载失败制造演示异常。
6. **原静态异常页**：原目录中的低水位 / 清洁提醒等直接展示路由保留，未一律重写为新引擎状态；本次稳定触发 / 重试 / 重置的验收范围以场景清单的 21 项为准。
7. **持久化**：新启动只保证异常注入清零；成功的模拟业务数据仍保留，完整重置可恢复初始入口与数据。未保存表单不跨主动页面跳转恢复。
8. **工程遗留**：保留上游平台模板和未启用的 server 文件 / 脚本，没有建设或启动后端。依赖树仍含上游历史安全告警，不适合直接用作生产后台；本次未做无关的全量依赖升级。构建仍有原大包体积告警。

## 扩展一个场景

先在 `catalog.ts` 注册完整契约，并绑定已存在的 operation；只有新增业务操作才需要注册 `useOperation`。保持失败不提交、重试不重复提交、路由取消、直接预览不写入的测试。不要修改真实网络环境或散落页面条件来模拟异常。
